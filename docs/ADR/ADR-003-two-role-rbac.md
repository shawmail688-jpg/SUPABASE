# ADR-003：权限两类角色（管理层 / 调查员），匿名零权限

Status：Accepted
Date：2026-09-03
决策者：用户（v1.3 第三轮 #6 定案）
来源：Proposal v1.3 §7①②、附录 A 第一轮 #9

# 一、背景（Context）

- 领导需要审批权；用户需要全量管理权；两人实际同权——若分「领导/管理员」两级反而制造假差异
- 调查员只交表，历史痛点：链接共享即全可见（Sheet 安全债）、anon 可读姿态（同事 schema 前科）
- 单一国家、≤20 店、十几人：无组织树、无跨区域 scope 需求

# 二、决策（Decision）

- 两类角色 + admin 附加位：**管理层**（用户+领导账号同权）=全量读写+审批+隐藏；**调查员**=仅 INSERT/UPDATE 自己提交的数据、不可 DELETE、不可改 status；**admin**（=用户本人）额外有恢复隐藏数据权；**anon 零权限**
- 实现走 Postgres RLS 行级策略，一人一号（admin 建号，不共用）
- UI 层同矩阵控制按钮渲染（双保险，但 RLS 是底线）

# 三、候选方案与取舍（Alternatives）

| 方案 | 理由 | 否决原因 |
|------|------|----------|
| **两类角色+admin** ✅ | 覆盖实际管理关系，RLS 策略最简 | — |
| Role+Scope 组织树权限（外评第一轮 #9） | 可扩展多国多组织 | 千店级组件；规模不匹配，外评已处置暂不采纳 |
| 维持匿名可读 | 零改动 | 安全债本体，必须还 |
| 三级角色（领导<管理员） | 职级映射 | 用户与领导实为同权，分级制造假差异 |

# 四、验证证据（如经评估 / 原型）

- 权限矩阵将在 M1 以「三角色×操作」用例机器验证——待实现
- 安全层代码另送 ChatGPT 手术式外审一次（§13 协作纪律）

# 五、后果（Consequences）

- 正面：谁提交谁审批全程可追溯；调查员越权在 DB 层即被拒（不依赖前端自觉）
- 代价 / 技术债：RLS 策略写错=权限失效，M1 必须用例覆盖到位；「自己的数据」判定依赖 created_by 字段纪律
- 回退触发条件：出现真实的多组织/多区域需求 → 走 C2 评估 Role+Scope（表结构预留 app_user.role 不阻碍）
