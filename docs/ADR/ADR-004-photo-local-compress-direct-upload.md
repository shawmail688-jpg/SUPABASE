# ADR-004：照片=设备本地压缩后直传 Storage 私有桶

Status：Accepted
Date：2026-09-03
决策者：用户（v1.2 附录 A 第二轮 #6 采纳+例外，v1.3 维持）
来源：Proposal v1.3 §4 决策 3、§7③

# 一、背景（Context）

- 现状：照片存本地文件夹，Atlas 靠本机隧道对外——办公室机器关机=照片全不可见
- 乌干达弱网：原图（数 MB）直传慢且易失败；Storage 流量费与照片体量正相关
- 部分场景（合同小字/车牌/仪表）不能压狠

# 二、决策（Decision）

- 链路：拍摄 → **设备本地压缩** → 直传 Storage 私有桶 → 短时效签名 URL 调阅
- 压缩参数：默认档长边 1600-2000px / JPEG 质量 ~80%（单张 300KB-1MB 量级）；「细节照」开关走高质量档（不压狠）
- 失败进离线队列自动重试；photo 表只存元数据（storage_path/sha1/taken_at/uploaded_by）
- 本地原图归档保留为既有行为，但**平台不依赖它**
- 存量照片一次性迁入 Storage+登记（09-03 用户裁定迁入）

# 三、候选方案与取舍（Alternatives）

| 方案 | 理由 | 否决原因 |
|------|------|----------|
| **本地压缩直传** ✅ | 省流量/弱网快/失败可队列重试 | — |
| 原图直传+服务端压缩 | 保真 | 3G 上传数 MB 易失败；服务端压缩消耗配额 |
| 默认本地原图冷备作为平台依赖 | 数据保险 | 外评第二轮 #6：平台不依赖本地；原图归档降级为既有行为 |
| 公开桶直链 | 实现简 | 租金/门头照片公开=安全债重演，私有桶+签名 URL 定案 |

# 四、验证证据（如经评估 / 原型）

- 压缩参数验收将在 M2a 以样本照片脚本断言（长边 ∈[1600,2000]、体积上限）——待实现
- 门头/道路/环境照 80% 质量肉眼无损为行业经验值（Theoretical/行业惯例，上线后用户实拍复核）

# 五、后果（Consequences）

- 正面：弱网可交；Storage 体量可控（数百 KB/张）；照片与库同生命周期（备份双保险覆盖）
- 代价 / 技术债：细节照开关依赖调查员正确使用；压缩不可逆（细节照没开开关则细节丢失）——缓解：高质量档上限放宽至 2.5MB
- 回退触发条件：出现「细节丢失」真实投诉 → 细节照档参数上调或该场景默认高质量
