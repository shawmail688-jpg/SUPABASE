# ADR-005：Sheets 降级为历史存档，管理操作全走网页（双向同步取消）

Status：Accepted
Date：2026-09-03
决策者：用户（批准后修订⑨，09-03 提出）
来源：Proposal v1.3 §9、§10 M4 行

# 一、背景（Context）

- v1.2 原设计：DB 权威+Sheets 业务工作台（双向同步），M4 里程碑
- 批准时用户提出：审批/隐藏/编辑/导出全部由网页（工作视图+领导视图）承接后，双向同步失去了存在理由
- 双向同步是全方案最易出 bug 的组件（冲突裁决/删行语义/who 缺失）

# 二、决策（Decision）

- **M4 Sheets 工作台化取消**：审批/隐藏/编辑/导出全走网页
- Sheets 迁移完成后冻结为**历史数据存档**（只读），不再是操作面、不是第二事实源
- 数据直看两路：工作视图（日常）+ Supabase Studio 表编辑器（admin 应急直查，零开发）
- §9 三条同步规则（删行归档/ID 列同步键/行级 last-write-wins）**降级为归档备轨**：未来重启约 2 天

# 三、候选方案与取舍（Alternatives）

| 方案 | 理由 | 否决原因 |
|------|------|----------|
| **网页全操作+Sheets 冻结存档** ✅ | 砍掉最易出 bug 组件；用户作为主要操作者选择网页 | — |
| Sheets 工作台化（v1.2 M4） | 沿用 Sheet 操作习惯 | 双向同步复杂度高、收益低（用户已选网页） |
| 立即物理下线 Sheet | 干净 | 历史数据留档价值；冻结只读即可 |

# 四、验证证据（如经评估 / 原型）

- 备轨规则已在 v1.3 §9 定稿（含删行事件无操作人的事实注记），重启时无需重新设计

# 五、后果（Consequences）

- 正面：系统少一个高危组件；M4 工时（≈2 天）转投 M3b 字段编辑+CSV 导出；总工期 9-11 天
- 代价 / 技术债：习惯 Sheet 的同事需要切换到网页（仅十几人，可控）；备轨代码不存在（重启需 2 天开发）
- 回退触发条件：用户或管理层实际使用后明确要求 Sheet 操作面 → 按备轨三规则重启（约 2 天，走 C2）
