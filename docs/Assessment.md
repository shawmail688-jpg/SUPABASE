# 二、硬触发检查

- [x] 新技术栈 / 新框架 / 新关键依赖 → 至少 Large（**命中**：Supabase 为承重新依赖，选型已论证、原型未做）
- [ ] 数据模型破坏性迁移（迁移非破坏：双轨并行、原数据保留、软删除）
- [ ] 架构层变更（新系统建设，非既有架构改造）
- [ ] 既有 API 契约破坏（无对外契约）
- [x] 安全 / 合规敏感 → 至少 Large（**命中**：认证+RLS 为系统核心，业务数据含租金/联系人上云）
- [ ] 多服务 / 多仓库 / 多利益相关方 / 不可逆操作 → 未命中 Enterprise（交付单人；迁移可回滚；无跨团队协调）
